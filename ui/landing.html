02

Agentic memory is not one thing. We store it as three.

Each is read at a different moment, written by different code, and lives for a different length of time. Collapsing them into one vector store is what makes agents feel amnesiac despite "having RAG".

03

The dangerous contract is the one that looks fine.

Pattern matching finds bad clauses that are present. It is blind to protections that are simply missing — which is how a polished, well-drafted template still leaves you exposed. So the agent checks your whole rule set against the document and reports what nobody wrote down.

Fig. C — vector search returns rules resembling the contract's contents, so a missing protection can never be retrieved that way. The full rule set is checked instead.

The payoff

A clause flagged across many clients isn't a client problem.

It's a missing term in your contract. No single review reaches that conclusion — it only exists because every decision was written somewhere queryable.

SELECT f->>'clause'                AS clause,
       count(*)                    AS times_flagged,
       count(DISTINCT client_name) AS clients
FROM   agent_audit_log,
       jsonb_array_elements(decision->'findings') AS f
GROUP  BY 1
ORDER  BY times_flagged DESC;
