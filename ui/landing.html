Architecture

Agentic memory is not one thing. We store it as three.

Each is read at a different moment, written by different code, and lives for a different length of time. Collapsing them into one vector store is what makes agents feel amnesiac despite “having RAG”.

Semantic

What I believe

Your standing terms and the clause patterns that have harmed you. Vector-searched per clause, so a contract about non-competes recalls different rules than one about payment.

AsyncCockroachDBVectorStore → guardian_memory
Episodic

What happened with this client

One durable thread per client. Reopening it months later replays the whole negotiation, so the agent never re-demands something you already conceded.

CockroachDBChatMessageHistory → guardian_chat_history
Procedural

Where the work got to

Workflow state checkpointed after every step. Kill the process mid-review and the next run resumes from the last completed node instead of starting over.

AsyncCockroachDBSaver → checkpoints
The workflow

Four steps, every one of them written down.

01

ingest_contract

Archives the original to S3, then splits it into clauses.

02

retrieve_memory

One vector query per clause across both namespaces, plus this client's thread.

03

analyze_contract

Scores commercial risk 0–100 and drafts a send-ready counter-offer.

04

save_state

Writes the decision to an append-only audit log and the client's thread.

The payoff

A clause flagged across many clients isn't a client problem.

It's a missing term in your contract. No single review can reach that conclusion — it only exists because every decision was written somewhere queryable.
